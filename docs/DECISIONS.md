# 試作の判断記録

この記録は制作を進めるための暫定実装判断。添付資料の「要決定」を製品仕様の承認済み事項に変更するものではない。
ユーザーの指定はSteam向け。Steamは配信先でありOS名ではないため、まずWindows x86_64、開発・検証用にLinux x86_64を採る。

| ID | 判断 | 理由と変更時の影響 |
|---|---|---|
| ADR-001 | Godot 4.6.3 / GDScript / Compatibility | ネイティブPC実行、ヘッドレス検証、外部ライセンスや認証を待たず開始可能。将来の大規模シミュレーションは別サーバーへ |
| ADR-002 | 初版はローカル単一プレイヤー、経済の判定をcoreへ集中 | 実際に触れる初期ループを先に検証。通信/認証/オンライン権威を実装済みとは扱わない |
| ADR-003 | commandにrequest IDとpayload hash、Mutexで直列化 | 成否と結果を再送時に再利用。同じIDで異なる内容を拒否。資産変更は成功時にまとめて保存、失敗時に元状態へ戻す |
| ADR-004 | 原子的なファイル置換＋1世代バックアップ | Godotのオブジェクト復元を無効にしたVariantデータをBase64+SHA-256のJSON封筒へ保存。金額の整数型・位置の精度を維持。DB/Outbox/電源断保証の代替ではない |
| ADR-005 | 1秒=ゲーム内1分、開始08:00、30分ごと集約 | 短時間で生産変化を観察。タイトル/終了中は止まる。NPC30日試験は1分刻みで実行 |
| ADR-006 | 銅貨整数、1枚4g/1mL、開始24銅貨 | 携行金にも重量を反映。初期総額1,074銅貨の各口座を明示。報酬・税・売買のために増発しない |
| ADR-007 | 24kg/30L、最大125%、銀行200kg/200L・手数料0 | 統合仕様の5段階負荷。硬貨を含めて最大の比率で判定。容器の入れ子/形状/分割スタックは後続 |
| ADR-008 | 死亡で携行品移転、Lv-2/最低1、携行金25%をlost勘定へ | 銀行は不変。遺品は固定の北遺跡回収箱へ。金銭損失は消去ではなく勘定移転。地理ごとの遺品位置は後続 |
| ADR-009 | 3素材、剣/傷薬、30NPC、2初期依頼、剣士/職人 | 1回の作業で遊べる最小範囲。職人の高度技能・希少職抽選はまだ未実装 |
| ADR-010 | 人工物は実入力を消費して生成 | 初期の剣/薬も初期素材から製造。製品に投入IDと製作者・起源イベントが残る |
| ADR-011 | Steamworks未組込み | App IDやSteamパートナー資格なしでローカル試作を開始。将来Steam認証・実績・Cloud・Inputを別境界で接続。Steamへ送信・公開はしない |
| ADR-012 | メニュー中も世界進行、FOV/感度/画面拡大 | 危険地帯で開く前にUIで説明。キー再割当・完全なパッド評価・Steam Deckは次工程 |

ローカルの `player.gd` は信頼された入力・物理ホストとして位置・スタミナをcoreに渡す。これはネットワーク上のクライアント申告を信頼してよいという設計ではない。段階6では同じ移動を権威プロセス側で計算し、クライアントには入力だけを送らせる。

現在のログと冪等結果はセーブに保持され続ける。100村/常時接続に拡大する前にイベント永続DB、アーカイブ、保持期間、復旧手順が必要。口座照合と保存則テストはその移行でも維持する。
