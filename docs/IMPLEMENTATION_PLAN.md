## 資料を読み合わせた結論

全100村・10,000NPCは最終的な検証目標であり、最初の必達規模ではない。初期MVPは1村・30～50NPC。
中心価値は会話AI単独ではなく、NPCの仕事、実物の生産・移転、地域価格、依頼、プレイヤーの行動の因果。
台帳が未整備のまま市場・銀行・死亡・報酬を作ると保存則を後から直すことになるため、資産基盤を先行する。
金融・保管・物流の統合仕様は、所有者・占有者・所在・保管安全性を区別する詳細として採用する。

## 0.2.0 の制作追加

三人称の追従カメラとカメラ方向基準の移動、建物とのカメラ衝突、成人体型のリグ付きオリジナル人物4種、役割別NPC表示、木組みや農地を増やした村、HP・スタミナ・目的・地図・装備のHUD、オリジナルBGM2曲と効果音4種、剛体の荷箱と押し出しを追加した。Godotの3D物理を60Hzで動かし、ソースと書き出し版のシーン検証を対象にする。

これは製品全体の完成判定ではない。人物の表情・衣装・装備差分、移動と戦闘のモーション、村の建築密度、遠景・照明・天候、敵種とボス、音響ミックス、入力再割当、Steamworks、Windows実機での長時間試験を、販売前の制作・品質ゲートとして残す。元の第10段階はSteam機能の実装順を表し、販売可能な完成度の判定とは別に管理する。

## 初版で遊べる縦の流れ

無垢で到着→掲示板で鉄不足の仕事→採集→納品→報酬→訓練・剣士、または製造・職人→売買→安全保管→遺跡で戦闘→死亡→銀行資産を保持して再出発→同じIDの遺品を回収。
別ルートとして、嵐で傷んだ北門へ木材を納品すると北門の状態と地域の木材需要が変わる。

## ここでは完成としないもの

依頼は2種類の初期テンプレートで、任意の社会事件から生成する汎用ジェネレーターはまだない。
NPCは日課と集約経済を持つ仮モデルで、完全な飢餓・給与・家計・経路探索・噂・相続モデルではない。
時間は実行中だけ進む。ログからの任意時点リプレイ、DB故障からの分散復旧、オンライン不正対策は未実装。
複雑な金融・融資・保険・馬車・船・PvP・銃・魔法を仮に有効化しない。プロトタイプのルール値は製品確定値ではない。

## 次に作る単位

最優先は独立プロセスの権威サーバーと永続DB。既存のコマンドと受入テストを移植し、認証主体の照合と権威側の移動・戦闘を追加する。
その後、村A→村Bの1本の街道で、現物貨物を集荷・輸送・受領する機能を作る。これがNPC発注・護衛・物流事故の基盤になる。
